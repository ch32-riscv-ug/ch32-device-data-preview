#### 18.2.1.6 USB Interrupt Status Register (R8_INT_ST)

<table><tr><th>Bit</th><th>Name</th><th>Access</th><th>Description</th><th>Reset value</th></tr><tr><td>7</td><td>SETUP_ACT</td><td>RO</td><td style="text-align:left">SETUP transaction complete 1: SETUP transaction complete;<br>0: No event.</td><td>0</td></tr><tr><td>6</td><td>RB_UIS_TOG_OK</td><td>RO</td><td style="text-align:left">Toggle of the received packet after the USB transaction reception is completed with the set expectation Match status bits:<br>1: Toggle matched;<br>0: Toggle does not match.</td><td>0</td></tr><tr><td>[5:4]</td><td>MASK_UIS_TOKEN</td><td>RO</td><td style="text-align:left">In device mode, the token PID identifier of the current USB transfer transaction.</td><td>XXb</td></tr><tr><td rowspan="2">[3:0]</td><td>MASK_UIS_ENDP</td><td>RO</td><td style="text-align:left">In device mode, the endpoint number of the current USB transfer transaction.</td><td>XXXXb</td></tr><tr><td>MASK_UIS_H_RES</td><td>RO</td><td style="text-align:left">In host mode, the response PID identifier of the current USB transmission transaction,<br>0000 means the device has no response or timed out; other values indicate the response PID.</td><td>XXXXb</td></tr></table>

<em>Note: MASK_UIS_TOKEN is used in USB device mode to identify the token PID of the current USB transmission</em>  
<em>transaction: 00 for OUT packets; 01 reserved; 10 for IN packets; 11 for SETUP packets.</em>  
<em>MASK_UIS_H_RES is only valid in host mode. In host mode, if the host sends an OUT/SETUP token packet, this</em>  
<em>PID is either a handshake packet ACK/NAK/STALL, or the device has no answer/timeout. If the host sends an IN</em>  
<em>token packet, this PID is either the packet PID (DATA0/DATA1) or the handshake packet PID.</em>

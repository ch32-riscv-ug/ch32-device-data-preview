When the SAI audio module is configured to operate in AC&#x27;97 mode (i.e., when the PRTCFG[1:0] bits in the  
R32_SAI_xCFGR1 register are set to 10b), the CNRDY flag in the R32_SAI_xSR register becomes meaningful.  
If the CNRDYIE bit in the R32_SAI_xINTENR register is set to 1, an interrupt will be generated when the  
CNRDY flag is set to 1.  
During reception of the TAG0 (slot0) AC&#x27;97 audio frame, if the codec is not yet ready for communication, the  
CNRDY flag will be set to 1. In this case, data will not be automatically stored into the FIFO until TAG0 indicates  
the codec is ready, because the codec is not yet prepared. Once the codec is ready, all valid slots defined in the  
R32_SAI_xSLOTR register will be captured.  
To clear the CNRDY flag, the CNRDY bit in the R32_SAI_xSR register must be written to 1.  
<strong>Master mode clock configuration error (NODIV=0)</strong>  
When the audio module works in the main mode (MODE[1:0]=0x) and the NODIV position is 0, if the following  
conditions are met, the WCKCFG flag will be set to 1 as long as SAI is enabled:  
- (FRL+1) is not a power of 2;
- (FRL+1) is not between 8 and 256.
The MODE bit, the NODIV bit and the SAIEN bit belong to the R32_SAI_xCFGR1 register, and the FRL bit  
belongs to the R32_SAI_xFRCR register.  
If the WCKCFGIE bit is set, an interrupt will be generated when the WCKCFG flag in the R32_SAI_xSR register  
is set. To clear this flag, write a 1 to bit WCKCFG in R32_SAI_xSR register.  
When WCKCFG is set to 1, the audio module is automatically disabled, so the SAIEN bit will be hardware  
cleared.  

### 36.3.13 DMA Interface

To reduce CPU load and optimize bus bandwidth, each SAI audio module features an independent DMA interface  
for read/write operations on the R32_SAI_xDATAR register (accessing the internal FIFO). Each audio submodule  
is equipped with a DMA channel supporting the basic DMA request/response protocol.  
When configuring DMA transfers to serve the audio submodule, set bit 1 of the DMAEN field in the  
R32_SAI_xCFGR1 register. DMA requests are directly managed by the FIFO controller, and their generation  
depends on the FIFO threshold. When the audio submodule is configured in transmit mode, the FIFO threshold  
must be set to a specific value to ensure sufficient remaining space for a complete DMA burst write operation  
under worst-case conditions. Failure to do so may result in a FIFO overflow error. When the audio submodule is  
configured in receive mode, the FIFO threshold must be set to a specific value to ensure sufficient data in the  
FIFO for a complete DMA burst read operation, thereby preventing FIFO underflow errors.  
The DMA transfer direction is related to the configuration of the SAI audio submodule:  
- If the audio module functions as a transmitter, the audio module&#x27;s FIFO controller will issue DMA requests to
load data written into the SAI_xDATAR register into the FIFO.  
- If the audio module functions as a receiver, DMA requests are associated with read operations from the
R32_SAI_xDATAR register.  
Configure the SAI interface for DMA mode in the following sequence:  
1) Configure the SAI and FIFO thresholds to specify when to initiate DMA requests.  
2) Configure the SAI DMA channel.  
3) Enable DMA.  
4) Enable the SAI interface.  
<em>Note: Before configuring the SAI module, the SAI DMA channel must be disabled.</em>

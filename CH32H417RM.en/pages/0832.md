## 38.3 Register Description


### 38.3.1 SWP Initialization and Activation

SWP initialization and activation transition the SWPMI_IO state from low to high. When using the internal  
transceiver, the software operation follows this sequence:  
1) Enable the SWPMI_IO transceiver via bit 1 of the R32_SWPMI_CR register (SWPTEN) and set SWPMI_IO  
to low (SWP bus “disabled”);  
2) Wait for bit 1 of the RDYF field in the R32_SWPMI_SR register (polling flag) or enable interrupts via the  
RDYIE bit in the R32_SWPMI_IER register;  
3) Set bit 1 of the SWPACT field in the R32_SWPMI_CR register to transition the SWP bus from “Disabled” to  
“Suspended” state, thereby activating SWP.  

### 38.3.2 SWP Bus Status

The SWP bus has three states: “Disabled,” “Suspended,” and “Activated.”  
State transitions include:  
● Activate: Transition from “Disabled” state to “Suspended” state;  
● Suspend: Transition from “Activated” state to “Suspended” state;  
● Disable: Transition from “Suspended” state to “Disabled” state;  
● Master Device Recovery: Transition initiated by the master device from “Suspended” state to “Activated”  
state;  
● Slave Device Recovery: Transition initiated by the slave device from “Suspended” state to “Activated” state.  
<strong>Activation</strong>  
During the reset phase and immediately after reset completion, SWPMI_IO is configured for emulation mode.  
Refer to Section 38.3.1 for the SWP bus activation procedure.  
<strong>Suspended</strong>  
If communication exists between the SWP bus and a slave device (regardless of whether in transmit or receive  
mode), the SWP bus remains in the “active” state. If no subsequent transmit or receive requests occur, the SWP  
bus will transition back to the “suspended” state after seven idle bits.  
<strong>Disable</strong>  
1) Disabling Request  
When the SWP is in the “Suspended” state, if communication is no longer required, the user may request  
switching the SWP to the ‘Disabled’ state by disabling the SWPMI peripheral. Setting the DEACT bit in the  
R32_SWPMI_CR register to 1 enables switching to the “Disabled” state. If the SWPMI does not detect a “Slave  
Device Recovery” state, the DEACTF bit in the R32_SWPMI_ISR register will be set to 1, and the SWPACT bit  
in the R32_SWPMI_ICR register will be cleared. If SWPMI detects a “Slave Device Recovery” state after  
DEACT is set to 1, the SRF flag in the R32_SWPMI_ISR register will be set to 1, DEACTF remains cleared,  
SWPACT remains set to 1, and the DEACT bit is cleared. Clear the DEACT bit in the R32_SWPMI_CR register,  
then set SWPACT to 1 to reactivate SWP.  
2) Disabled Mode  
The user must clear the SWPACT bit in the R32_SWPMI_CR register for the SWP to immediately transition to  
the “Disabled” mode and ignore any incoming “Slave Device Recovery” state.  
<em>Note: To further reduce current consumption, configure the SWPMI_IO port in the GPIO controller to push-pull</em>

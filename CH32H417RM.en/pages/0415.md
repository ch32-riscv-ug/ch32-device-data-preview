● RXDMAEN: Enable/disable DMA mode for the RX-FIFO  
● RXTHRES: Pop data bytes or words from the RX-FIFO  
Then, read the RX-FIFO according to the RXDMAEN bit:  
● Software reads directly by byte/word (RXDMAEN=0):  
–Through polling mode (RXFNEIE=0 in R32_I3C_INTENR register): Wait for the hardware to request the next  
data byte/word (RXFNEF=1 in R32_I3C_INTENR register) before explicitly reading R32_I3C_RDR or  
R32_I3C_RDWR register, depending on R32_I3C_CGFR register.  
–Notify via enabled interrupt (if R32_I3C_INTENR register RXFNEIE=1)  
● Read by the assigned DMA channel (if RXDMAEN=1) to enable the corresponding I3C peripheral DMA  
request:  
–According to the configuration at DMA module level, DMA will automatically pop up/read data bytes/words  
from R32_I3C_RDR or R32_I3C_RDWR register (depending on the RXTHRES bit) and write them into its  
memory slave buffer until the frame is completed (after the last message of the frame, a stop bit will be issued on  
the I3C bus), except when a transmission error occurs.  
I3C messages start with a start bit or a repeat start bit and end with a stop bit or a repeat start bit. At the message  
level, the last data byte/word received from the I3C bus is indicated by IRXLASTF=1 in the I3C_EVR register.  
When the I3C frame contains multiple messages (separated by repeated start bits), the software can use this event  
to update the corresponding pointer to the buffer for storing the data byte/word of the next message.  
If the RX-FIFO is full and data bytes are received on the I3C bus, the RX-FIFO overflow will be reported  
(ERRF=1 in the R32_I3C_EVR register and DOVR=1 in the R32_I3C_STATER register). If the corresponding  
interrupt is enabled (ERRIE=1 in the R32_I3C_INTENR register), an interrupt is generated.  
When the I3C peripheral is not working, the configuration of RX-FIFO management can be modified.  
<strong>Device early termination of read transfer</strong>  
Disabling the S-FIFO (SMODE=0 in the R32_I3C_CFGR register) will notify the software of a read transfer  
premature termination via RXTGTENDF=1 in the R32_I3C_EVR register and the corresponding interrupt (if  
enabled). The software can then read the status register R32_I3C_STATR to examine information related to the  
last message and obtain the number of data bytes received during the prematurely terminated read transfer  
(XDCNT[15:0] in the R32_I3C_STATR register).  
In any case, if the S-FIFO is enabled (SMODE=1 in the R32_I3C_CFGR register), the software or DMA  
(depending on SDMAEN in the R32_I3C_CFGR register) must read the status register R32_I3C_STATR once for  
each message. The number of valid data bytes received in a preemptively terminated read message is reported by  
XDCNT[15:0] in the R32_I3C_STATR register (followed by ABT=1).  

#### 22.3.5.4 S-FIFO Management (as master)

When used as a master device, the software can read the I3C status register (R32_I3C_STATR) for each  
transmitted message using the S-FIFO.  
<strong>Reading status register when S-FIFO is disabled</strong>  
When the SMODE bit of the R32_I3C_CFGR register is set to 0, the S-FIFO is disabled, and the reading mode of  
the status register is the same as that of a normal register:  
● When transmitting a new message, the register contents are overwritten by hardware.

### 40.3.1 Supported Memory and Transactions

<strong>Common transaction rules</strong>  
The HB transaction data width requested is 8, 16, 32, or 256 bits, whereas the external device accessed has a fixed  
data width. This difference can cause data width mismatch problems. To avoid this problem, the transaction rules  
to follow are as follows:  
● HB transaction data width equals memory data width: Normal operation.  
● HB transaction data width exceeds memory width: The FMC splits the HB transaction into multiple smaller  
contiguous memory accesses to match the external data width. The FMC chip select (FMC_NEx) does not  
toggle between contiguous accesses.  
● HB transaction data width is less than memory width: Transfer consistency may be affected, depending on  
the type of external device.  
- Accessing devices with byte selection capability (ROM, SRAM, SDRAM, PSRAM): The FMC permits
read and write transactions, accessing the correct data through its byte select lines NBL[1:0]. The byte  
to be written is addressed via NBL[1:0]. All memory bytes are read (NBL[1:0] remains low during read  
transactions), with invalid bytes subsequently discarded.  
- Accessing devices without byte selection capability (NOR, NAND Flash): This occurs when byte access
is required for 16-bit wide FLASH memory. Since these devices do not support byte-mode access (only  
allowing 16-bit words to be read from or written to Flash), read transactions are permitted but write  
transactions are not (the controller reads the entire 16-bit memory word but uses only the required  
byte).  
<strong>NOR Flash/PSRAM and SDRAM rewinding support</strong>  
Since not all masters can issue rollback transactions, synchronous memory must be configured in a linear burst  
mode of undefined length. If a master generates HB rollback transactions:  
● Read operations will be divided into two linear burst transactions.  
● If the write FIFO is enabled, write operations will be divided into two linear burst transactions; if the write  
FIFO is disabled, write operations will be divided into multiple linear burst transactions.

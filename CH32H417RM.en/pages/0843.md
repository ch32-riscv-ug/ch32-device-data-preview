If the application software cannot guarantee processing the SMPMI interrupt before receiving the next frame, each  
buffer status will be presented in the most significant byte of the 8th buffer word:  
● Receive Overflow Flag: The RXOVRF flag in the R32_SWPMI_ISR register, indicated by bit 25 of the  
eighth word. For details on overflow errors, refer to Section 38.3.8.  
● Receive Buffer Full Flag: The RXBFF flag in the R32_SWPMI_ISR register, indicated by bit 26 of the  
eighth word.  
● CRC error flag: The RXBERF flag in the R32_SWPMI_ISR register, indicated by bit 24 of the 8th word. For  
details on CRC errors, see Section 38.3.8.  
When a CRC error occurs, both the RXBFF and RXBERF flags are set to 1, meaning bits 24 and 26 will be set to  
1. When an overflow occurs, the overflow flag bit is set to 1, i.e., bit 25 is set to 1. The receive buffer full flag is  
only set to 1 if the overflow occurs during the reception of the last byte; Subsequently, for both the current and  
next frame reception, bits 25 and 26 will be set to 1.  
Software can read the DMA counter in the DMA register to retrieve frames transferred via DMA and stored in  
RAM. For example, if software uses 4 receive buffers and the DMA counter value equals 17, this indicates two  
buffers are ready for software readout in the RAM region. In multi-software buffer reception mode, if the software  
is reading bits 24, 25, and 26 of the eighth word, the RXBERF, RXOVRF, and RXBFF flags need not be cleared  
after each received frame.  

### 38.3.8 Error Management

<strong>Underflow occurred during payload transmission</strong>  
In the process of transmitting the frame payload, if the transmission underflow occurs, the TXUNRF flag in  
R32_SWPMI_ISR register will be triggered as a warning. If the TXBUNREIE bit in R32_SWPMI_IER register is  
set, an interrupt will be generated. When transmission underflow occurs, SWPMI will stop sending payload and  
send damaged CRC (the first bit of the first CRC byte sent is inverted), followed by EOF flag. If DMA is used, the  
TXDMA bit in R32_SWPMI_CR register will be cleared automatically.  
When TXUNRF is set to 1, any writing to the R32_SWPMI_TDR register is ignored. The user must set the  
CTXUNRF bit of R32_SWPMI_ICR register to 1 to clear the TXUNRF flag.  
<strong>Overflow occurred during payload reception</strong>  
In the process of receiving the frame payload, if there is reception overflow, the RXOVRF flag in  
R32_SWPMI_ISR register will be triggered as a warning. When receiving overflow occurs, the incoming data  
will not be used by SWPMI to update R32_SWPMI_RDR, so the incoming data will be lost.  
Data reception continues until EOF. Once the overflow condition ceases, the RXBFF flag will be set to 1. When  
the RXBFF flag is set, the user may check the RXOVRF flag. To clear the RXOVRF flag, the user must set the  
CRXOVRF bit in the R32_SWPMI_ICR register to 1. If immediate overflow detection is required, set the  
RXBOVREIE bit in the R32_SWPMI_IER register to ensure an immediate interrupt trigger upon overflow  
occurrence.  
When both the RXOVRF and RXNE flags are set, two R32_SWPMI_RDR read operations will execute following  
an overflow event. This indicates that at least one received byte was lost, and the byte loaded into  
R32_SWPMI_RDR contains the byte received immediately before the overflow occurred.

<strong>Initiates a transfer initiated from the device</strong>  
When a device transitions from the disabled state to the idle state (software writes 1 to the EN bit in the  
R32_I3C_CFGR register) and is simultaneously capable of receiving the master device&#x27;s broadcast CCC, the  
software may issue a hot join request (software writes 1000b to the MTYPE[3:0] bits in the R32_I3C_CTLR  
register) to apply for eligibility to join the next ENTDAACCC. This is contingent upon the hot join request being  
enabled (set HJEN bit to 1 in the R32_I3C_DEVR0 register).  
After dynamic address allocation (R32_I3C_EVR register DAUPF bit 1 set) – typically concurrent with frame  
transmission initiated by the master device – the software may issue an IBI (in-band interrupt request) or master  
role request to the master device by writing the relevant control word to the R32_I3C_CTLR register.  
<strong>Update the configuration of I3C peripherals (as slaves)</strong>  
After returning to the idle state, the software can update the configuration of the I3C slave device before the next  
transmission:  
- Configure the R32_I3C_INTENR register to modify the interrupt/polling mode strategy
- Configure the TXTHRES, RXTHRES, TXDMAEN, and RXDMAEN bits in the R32_I3C_CFGR register
- Modify/prepare the I3CIBI payload data register (R32_I3C_IBIDR). If any payload exists (when bit BCR2 in
the R32_I3C_BCR register is set to 1), this operation should be performed before initiating the IBI transfer  
(writing the MTYPE[3:0] bits to 1010b in the I3C Message Control Register [Multiplex] (R32_I3C_CTLR) with  
MTYPE[3:0] set to 1010b)  
- Modify/prepare the I3C slave device transmission configuration register (R32_I3C_TGTTDR). Before receiving
a private read or direct CCC read message (excluding GETSTATUS CCC) from the master device, disable or  
enable the TX-FIFO to preload the specified number of bytes of data to be transmitted.

### 34.4.4 Address Register of Indirect Addressed 2 (SFR_INDIR_ADDR2)

These are 2 sets of indirect address registers, each consisting of an address register and a data read/write port. First,  
write the destination register&#x27;s address into the address register. Then, read or write the destination register by  
accessing the data read/write port.  
The data read/write port SFR_INDIR_PORT for indirect addressing reads/writes the destination register specified  
by the indirectly addressed address register SFR_INDIR_ADDR. The data read/write port SFR_INDIR_PORT2  
for indirect addressing reads/writes the destination register specified by the indirectly addressed address register  
SFR_INDIR_ADDR2.  
The dedicated instruction MOVIP is used to load an 8-bit destination address into SFR_INDIR_ADDR.  
Additionally, SFR_INDIR_ADDR can be modified independently by other non-dedicated instructions.  
The dedicated instruction MOVIA is used to load an 8-bit target address into SFR_INDIR_ADDR2, and  
SFR_INDIR_ADDR2 can also be independently modified by other non-dedicated instructions.  
The address register SFR_INDIR_ADDR2 for Indirect Addressing Mode 2 features automatic incrementing.  
When executing the “MOV SFR_INDIR_PORT2,A” read instruction or the “MOVA SFR_INDIR_PORT2” write  
instruction to RAM, SFR_INDIR_ADDR2 will automatically increment by 1 upon instruction completion.  
The dedicated instructions MOVA1P and MOVA2P are used to directly and rapidly write operands from the  
instruction code into target registers, equivalent to performing immediate addressing followed by indirect  
addressing within a single cycle.  

### 34.4.5 Status Register (SFR_STATUS_REG)

The status register contains the result status of the ALU, general-purpose bit variables, and stack usage flags. After  
executing arithmetic or logical operations, the eMCU sets corresponding status bits based on the results, enabling  
the program to make judgments and perform further processing. General-purpose bit variables can be defined for  
specific purposes by the application.  
The timer timeout reset monitors the timeout of WAITB wait instructions. After disabling SB_TMR0_ENABLE  
and enabling SB_EN_TOUT_RST, the timer counts during WAITB execution. When overflow occurs and  
SB_TMR0_CYCLE is 1, a timeout reset is triggered. The timer initial value is automatically reloaded each time  
the WAITB instruction exits the WAITB wait state upon condition fulfillment. Counting does not occur during  
execution of non-WAITB instructions when SB_TMR0_ENABLE is 0, meaning the timer timeout reset applies  
exclusively to the WAITB instruction.

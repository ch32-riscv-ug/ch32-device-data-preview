### 20.2.2 Receive Mode (Interrupt Mode)

1. Set SERDESx_CTRL register  
PWR_UP/RX_PWR_UP/LINK_RESET/ALL_CLR is 1;  
2. Wait PLL locked (PLL_LOCK=1);  
3. Set SERDESx_CTRL register  
PWR_UP/RX_PWR_UP/ DMA_EN/RX_EN is 1;  
4. Set receive DMA address (Dual buffering mode is recommended.);  
5. Enable interrupts RECV_DONE_IE/COMINIT_IE/FIFO_OV_IE;  
6. After reception completes, check RECV_CRC_OK/RX_SEQ_MATCH. If in dual-buffered mode, query  
the least significant bit of RX_SEQ_NUM to determine which register is used for the current received  
packet: DATA0/DMA0/RX_LEN0 or DATA1/DMA1/RX_LEN1;  
RX_SEQ_NUM[0] is 1, indicating the current received packet uses DATA0/DMA0/RX_LEN0;  
RX_SEQ_NUM[0] is 0, indicating the current received packet uses DATA1/DMA1/RX_LEN1.  
<em>Note: RX_SEQ_NUM automatically adds 1 after receiving, so the RX_SEQ_NUM queried after receiving is</em>  
<em>subtracted from 1 to become the SEQ_NUM of the currently received packet.</em>  

### 20.2.3 Software Considerations:

1. The internal clock frequency SERDES_CLK within the controller is the PLL frequency divided by 40. For  
example, at 1.2GHz, SERDES_CLK is 30MHz.  
2. The return values of LINK_RESET, RX_EN, and TX_VLD are synchronized by SERDES_CLK, resulting in  
read delays;  
3. The length of transmitted or received data packets does not include the 4-byte length of DATA0/DATA1;  
4. After transmission completes, TX_VLD must be cleared first. Only after verifying this bit returns 0 should the  
transmission complete interrupt flag be cleared; otherwise, asynchronous issues may occur.

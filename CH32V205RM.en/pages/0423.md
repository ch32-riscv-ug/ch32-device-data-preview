When writing to the control register (R32_QSPIx_CR), the user can specify the following settings:  
● Enable bit (EN) set to 1  
● Timeout counter enable bit (TCEN)  
● FIFO threshold (FTRHES), indicating when the FTF flag should be set to 1  
● Interrupt enable  
● Auto-polling mode parameters: Match mode and Stop mode (effective when FMODE=11b)  
● Clock prescaler  
When writing to the communication configuration register (R32_QSPIx_CCR), the user specifies the following  
parameters:  
● DCYC bit specifies the number of empty instruction bytes  
● DBMODE bit specifies whether empty instruction bytes exist  
● INSTRUCTION bit specifies the instruction byte  
● Specify the number of alternate bytes (1/2/3/4) via the ABSIZE bit  
● Specify the instruction transmission mode (1/2/4-wire) via the IMODE bit  
● Specify the address length (8/16/24/32 bits) via the ADSIZE bit  
● Specify the address transmission mode (none/1/2/4-wire) via the ADMODE bit  
● Specify alternate byte transmission mode (None/1-wire/2-wire/4-wire) via the ABMODE bit  
● Specify data transmission/reception mode (None/1-wire/2-wire/4-wire) via the DMODE bit  
If no data register (R32_QSPIx_DR) or address register (R32_QSPIx_AR) needs updating for a command, the  
command sequence initiates immediately upon writing the R32_QSPIx_CCR register. This occurs when both  
ADMODE and DMODE are 00b, or when ADMODE=00b alone in indirect read mode (FMODE=01b). When an  
address is required (ADMODE ≠ 00) and no data register write is needed (FMODE = 01b or DMODE = 00b), the  
command sequence starts immediately upon updating the address via writing to the R32_QSPIx_AR register. In  
data transfer scenarios (FMODE=00b and DMODE!=00b), writing to the FIFO via the R32_QSPIx_DR register  
triggers communication initiation.  
<strong>Status Flag Polling Mode</strong>  
Enable Status Flag Polling Mode: Set the FMODE field in the R32_QSPIx_CCR register to 10b. In this mode,  
programmed frames are sent and data is periodically retrieved. The maximum data read per frame is 4 bytes. If the  
data requested in the R32_QSPIx_DLR register exceeds 4 bytes, the excess is ignored and only 4 bytes are read.  
The periodicity is specified by the R32_QSPIx_PISR register.  
After retrieving status data, it can be processed internally to achieve the following purposes:  
● Automatically stops periodic status byte retrieval  
● Sets the status match flag to 1 and generates an interrupt when enabled  
The received value can be masked using the value stored in the R32_QSPIx_PSMKR register, and then ORed or  
ANDed with the value stored in the R32_QSPIx_PSMAR register. If a match exists, the status match flag is set to  
1 and an interrupt is generated if enabled; if AMPS is set to 1, the QSPI automatically stops. In all cases, the latest  
read value is available in the R32_QSPIx_DR register.

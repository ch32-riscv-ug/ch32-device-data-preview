I3C messages start with a start bit or a repeat start bit and end with a stop bit or a repeat start bit. At the message  
level, the last data byte/word received from the I3C bus is indicated by IRXLASTF=1 in the I3C_EVR register.  
When the I3C frame contains multiple messages (separated by repeated start bits), the software can use this  
event to update the corresponding pointer to the buffer for storing the data byte/word of the next message.  
If the RX-FIFO is full and data bytes are received on the I3C bus, the RX-FIFO overflow will be reported  
(ERRF=1 in the R32_I3C_EVR register and DOVR=1 in the R32_I3C_STATER register). If the  
corresponding interrupt is enabled (ERRIE=1 in the R32_I3C_INTENR register), an interrupt is generated.  
When the I3C peripheral is not working, the configuration of RX-FIFO management can be modified.  
<strong>Device early termination of read transfer</strong>  
Disabling the S-FIFO (SMODE=0 in the R32_I3C_CFGR register) will notify the software of a read transfer  
premature termination via RXTGTENDF=1 in the R32_I3C_EVR register and the corresponding interrupt (if  
enabled). The software can then read the status register R32_I3C_STATR to examine information related to  
the last message and obtain the number of data bytes received during the prematurely terminated read transfer  
(XDCNT[15:0] in the R32_I3C_STATR register).  
In any case, if the S-FIFO is enabled (SMODE=1 in the R32_I3C_CFGR register), the software or DMA  
(depending on SDMAEN in the R32_I3C_CFGR register) must read the status register R32_I3C_STATR once  
for each message. The number of valid data bytes received in a preemptively terminated read message is  
reported by XDCNT[15:0] in the R32_I3C_STATR register (followed by ABT=1).

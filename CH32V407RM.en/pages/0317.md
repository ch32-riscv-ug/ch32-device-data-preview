When the report frame completes (R32_I3C_EVR register FCF = 1 and the corresponding interrupt is enabled),  
the TX-FIFO is empty. If the TX-FIFO is empty and a data byte must be transmitted on the I3C bus, a TX-  
FIFO underflow is reported (R32_I3C_EVR register ERRF = 1 and R32_I3C_STATER register DOVR = 1).  
If the corresponding interrupt is enabled (R32_I3C_INTENR register ERRIE = 1), an interrupt is generated.  
When the I3C peripheral is not active, the configuration managing the TX-FIFO can be modified.  
When operating as a master device, the hardware automatically clears the TX-FIFO upon a transmission error  
(ERRF = 1).  
<strong>No C-FIFO/TX-FIFO preload</strong>  
C-FIFO size is 2 words and TX-FIFO size is 8 bytes.  
When the preload function of the C-FIFO/TX-FIFO is not enabled, that is, the R32_I3C_CFGR register  
TMODE=0, once the C-FIFO receives the first control word, the I3C peripheral will immediately send out the  
start bit on the I3C bus. Subsequently, the peripheral will decode the R32_I3C_CTLR register and write the  
next data byte or word as needed. Once it is detected that the hardware requires to send the next control word  
on the I3C bus (for example, it is necessary to send a repeated start bit on the I3C bus or the C-FIFO needs to  
obtain available space), the peripheral will immediately request to write the control word into the C-FIFO until  
the last message (that is, R32_I3C_CTLR register MEND=1). Similarly, once it is detected that the hardware  
requires another data byte or word to be sent on the I3C bus (for example, a repeated start bit needs to be sent  
on the I3C bus, the TX-FIFO is not full, or the data byte or word must be sent during the I3C message), the  
data byte/word must be written into the TX-FIFO immediately.  
<strong>C-FIFO/TX-FIFO preload</strong>  
When C-FIFO/TX-FIFO preload is configured (R32_I3C_CFGR register TMODE = 1), I3C peripherals need  
to wait for C-FIFO and TX-FIFO to load as much as possible before sending out the start bit on the bus, as  
follows:  
Wait for the first control word to be written to the C-FIFO. Wait for data bytes/words to be written to the TX-  
FIFO (if any), as defined by the first control word (if RNW=0 in the R32_I3C_CTLR register and  
DCNT[15:0]=0), up to the size of the TX-FIFO. If TX-FIFO is not full and the first control word is not the  
final message in the frame (MEND=0 in the R32_I3C_CTLR register):  
–Wait for the second control word to be written into the C-FIFO, after which the C-FIFO becomes full.  
–If the TX-FIFO is not full, wait for data bytes/words to be written into the TX-FIFO (if any), as defined by  
the second control word (RNW=0 in the R32_I3C_CTLR register and DCNT[15:0]), up to the maximum size  
of the TX-FIFO.  
Then, whenever the hardware detects a requirement to transmit the next control word on the I3C bus (if a  
duplicate start bit must be sent on the I3C bus), it immediately requests that control word be written into the  
C-FIFO, continuing until the final message (MEND=1 in the R32_I3C_CTLR register).  
Similarly, whenever a hardware request is detected to send the next data byte/word on the I3C bus (if a repeat  
start bit must be issued on the I3C bus, the TX-FIFO is not full, or data bytes/words will be sent during that  
I3C message), that data byte/word must be written to the TX-FIFO immediately.
